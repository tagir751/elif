# План ручного тестирования MVP «Элиф»

**Цель:** Проверить полный цикл взаимодействия всех сущностей системы, правильность ролевой модели, целостность данных и работу основных экранов.

**Предусловия:**
- База данных: удалить `prisma/dev.db`, выполнить `npx prisma db push`, затем `npm run seed` (если нужно начать с демо-данных) или пропустить seed для пустой БД.
- Приложение запущено локально (`npm run dev`), доступны все API и фронтенд.
- Учётная запись администратора создана (email: `admin@elif.ru`, пароль: `admin123`).

---

## 1. Администратор: создание справочников и пользователей

### 1.1 Создание педагога (через админку)
1. Войти как `admin@elif.ru`.
2. Перейти в раздел «Пользователи» → «Создать пользователя».
3. Ввести:
   - Email: `maria@elif.ru`
   - Пароль: `teacher123`
   - Роль: Педагог
4. Нажать «Создать».
5. **Ожидаемый результат:** Пользователь появляется в списке, в БД созданы записи `user` и `teacher`.

### 1.2 Создание менеджера с двойной ролью
1. Создать пользователя:
   - Email: `anna@elif.ru`
   - Пароль: `manager123`
   - Роль: Менеджер
2. После создания нажать ✏️ рядом с пользователем — откроется редактор ролей.
3. Добавить роль «Педагог» (кликнуть по чипсу), нажать «Сохранить».
4. **Ожидаемый результат:** У пользователя `anna@elif.ru` роли `["manager", "teacher"]`, в шапке появилась кнопка переключения ролей.

### 1.3 Создание кабинетов (через API или раздел «Кабинеты» у менеджера)
1. Войти как менеджер (можно не выходить — переключить роль), перейти в «Ещё» → «Кабинеты».
2. Создать:
   - «Кабинет 3», ул. Ленина 5, вместимость 12
   - «Робозал», ул. Ленина 5, вместимость 10
3. **Ожидаемый результат:** Оба кабинета созданы, отображаются в списке.

### 1.4 Создание предметов (через админку)
1. Войти как админ → «Справочники».
2. Добавить предметы: «Английский», «Робототехника».
3. **Ожидаемый результат:** Предметы доступны в справочнике.

## 2. Менеджер: создание семей, учеников, групп, зачисление

### 2.1 Вход под менеджером
1. Выйти из админа, войти как `anna@elif.ru` (менеджер).
2. Убедиться, что открывается экран «Сегодня» с алертами (пустыми, если БД чиста).

### 2.2 Создание семьи
1. Перейти в раздел «Семьи» → «+ Новая семья».
2. Ввести:
   - Фамилия: Ивановы
   - Телефон: +79001234567
   - Email: ivanov@mail.ru
   - Месячная плата: 8000
   - Оплачено до: (дата через месяц)
3. Сохранить.
4. **Ожидаемый результат:** Семья отображается в списке, статус оплаты — зелёный.

### 2.3 Создание учеников и привязка к семье
1. Перейти в «Ученики» → «Добавить ученика».
2. Ввести: Артём, Иванов, дата рождения 15.03.2015.
3. Выбрать семью «Ивановы» из выпадающего списка.
4. **Примечание:** Если семьи ещё нет — нажать «➕ Новая семья» под списком, ввести название и телефон, семья создастся и автоматически выберется.
5. Создать второго ученика: София, Иванова, 22.07.2017, семья Ивановы.
6. **Ожидаемый результат:** Оба ученика привязаны к семье Ивановы.

### 2.4 Создание группы и назначение педагога
1. Перейти в «Группы» → «Создать группу».
2. Заполнить:
   - Название: Английский А1
   - Предмет: Английский
   - Педагог: Мария Иванова (создана в п.1.1)
   - Кабинет: Кабинет 3
   - Вместимость: 8
3. Сохранить.
4. **Ожидаемый результат:** Группа создана, педагог назначен.

### 2.5 Настройка расписания группы
1. В карточке группы «Английский А1» нажать «Добавить слот».
2. Выбрать: Понедельник, 17:00, Кабинет 3.
3. Добавить второй слот: Среда, 17:00, Кабинет 3.
4. **Ожидаемый результат:** Слоты отображаются в карточке.

### 2.6 Зачисление учеников в группу
1. В карточке группы «Английский А1» нажать «Добавить ученика» → выбрать Артёма.
2. Повторить для Софии.
3. **Ожидаемый результат:** Оба ученика отображаются в составе группы.

### 2.7 Повторное зачисление (проверка конфликта)
1. Попробовать снова зачислить Артёма в «Английский А1».
2. **Ожидаемый результат:** API возвращает 409 Conflict.

## 3. Финансы: оплата и продление

### 3.1 Просмотр статуса оплаты в карточке ученика
1. Открыть карточку Артёма.
2. В блоке «Семья» проверить: отображается название семьи, статус оплаты (✅ Оплачено до …) и зелёный цвет.
3. **Ожидаемый результат:** Финансовый блок виден только менеджеру (не педагогу). Вместо «баланса» отображается `paidUntil` — дата, до которой семья оплатила обучение.

### 3.2 Продление оплаты
1. В карточке семьи Ивановых нажать «Добавить платёж».
2. Ввести сумму 8000, дату сегодня, оплачено до = через месяц.
3. **Ожидаемый результат:** `paidUntil` сдвинулось на месяц вперёд. В аудите запись «создан платёж».

### 3.3 Просрочка оплаты
1. Изменить `paidUntil` семьи Ивановых на прошедшую дату (через API или редактирование в карточке семьи).
2. Перейти на экран «Сегодня».
3. **Ожидаемый результат:** В блоке «Требуют внимания» появляется алерт «🔴 Просрочка оплаты: семья Ивановы».

---

## 4. Педагог: работа с занятием, посещаемость, наблюдения

### 4.1 Вход под педагогом
1. Выйти из менеджера, войти как `maria@elif.ru` (педагог).
2. Убедиться, что открывается список сегодняшних занятий.

### 4.2 Проверка доступа
1. Попробовать открыть раздел «Семьи» или раздел с задачами.
2. **Ожидаемый результат:** Разделы недоступны, при прямом запросе API возвращает 403.

### 4.3 Открытие занятия (сначала сгенерировать)
1. Войти как менеджер, перейти в «Занятия» → нажать «Сгенерировать».
2. Выйти из менеджера, войти как педагог.
3. Выбрать занятие «Английский А1» на сегодня (или ближайшее).
4. Убедиться, что отображаются зачисленные ученики: Артём и София.

### 4.4 Отметка посещаемости
1. Для Артёма нажать «Был», оценка 5.
2. Для Софии нажать «Не был».
3. **Ожидаемый результат:**
   - Артём: status=present, mark=5.
   - София: status=absent, mark=null.
   - Чипсы подсвечиваются соответствующими цветами.

### 4.5 Добавление наблюдения
1. Нажать кнопку 💬 рядом с Артёмом.
2. Ввести текст: «Активно работал в группе, помогал другим».
3. Сохранить, затем опубликовать.
4. **Ожидаемый результат:** observation создан со статусом published, отображается в карточке ученика (вкладка «Развитие») и в ленте наблюдений.

### 4.6 Версионирование наблюдения
1. Отредактировать это же наблюдение (изменить текст).
2. Сохранить.
3. **Ожидаемый результат:** В БД создана запись в `observation_versions` со старым текстом.

### 4.7 Завершение урока
1. Нажать «Завершить урок».
2. **Ожидаемый результат:** Статус урока меняется на completed, все оценки сохранены.

## 5. Менеджер: просмотр истории и аналитика

### 5.1 Лента наблюдений
1. Войти как менеджер (или переключиться на роль менеджера).
2. Открыть раздел «Наблюдения».
3. Убедиться, что наблюдение про Артёма отображается с группировкой по дате.

### 5.2 Карточка ученика — вкладки «История» и «Развитие»
1. Открыть карточку Артёма.
2. Вкладка **«История»**: список групп (текущие зачисления) + посещаемость (все отметки цветными индикаторами).
3. Переключиться на вкладку **«Развитие»**: список наблюдений.
4. **Ожидаемый результат:** Табы переключаются, данные корректны.

### 5.3 Пропуски и алерты
1. Через API проставить Софии 3 `absent` подряд на разных занятиях.
2. Перейти на экран «Сегодня» под менеджером.
3. **Ожидаемый результат:** Алерт «🟡 Пропуски: София — 3 пропуска подряд».

## 6. Переключение ролей и комбинированный доступ

### 6.1 Переключение с менеджера на педагога
1. Войти как `anna@elif.ru` (имеет обе роли).
2. В шапке нажать «Переключиться на педагога».
3. Убедиться, что интерфейс сменился на педагогический (пропали финансы, задачи, остались только свои занятия и ученики).
4. Переключиться обратно на менеджера.

### 6.2 Проверка изоляции данных
1. Под педагогом `maria@elif.ru` открыть список учеников.
2. Убедиться, что видны только ученики её групп (Артём и София).
3. **Ожидаемый результат:** Ученики других педагогов не отображаются.

## 7. Задачи менеджера

1. Войти как менеджер.
2. Создать задачу «Позвонить маме Артёма» с типом 📞, привязать к семье Ивановых.
3. Перенести задачу в корзину «Ожидание».
4. Отметить как выполненную.
5. Убедиться, что задача исчезла из активных и появилась в выполненных.

## 8. Администратор: контроль и аудит

1. Войти как админ.
2. Открыть «Журнал действий»: проверить, что все операции (создание пользователей, изменение оплаты, добавление наблюдений) запротоколированы.
3. Скачать бэкап БД (кнопка «Скачать .db»). Убедиться, что файл содержит все таблицы.
4. Создать бэкап (кнопка «Создать бэкап сейчас»).
5. Проверить «Состояние системы»: количество пользователей, учеников, семей, наблюдений соответствует ожидаемому.

---

## 9. Проверка целостности данных (через API или админку)

- Каждый student имеет валидный familyId.
- Каждый enrollment ссылается на существующие student и group.
- Каждая attendance ссылается на существующие lesson и student.
- Нет дублирующихся email в users.
- Нет дублирующихся записей attendance для одной пары (lessonId, studentId).

---

## 10. Критерии успешного завершения теста

- Все шаги выполнены без ошибок.
- Ролевая модель соблюдена: педагог не видит финансы и чужие группы, менеджер не имеет доступа к админке.
- Наблюдения версионируются, удалённые записи не теряются (soft delete).
- Алерты на экране «Сегодня» корректно отображают проблемы.
- Журнал аудита фиксирует все значимые действия.

После успешного прохождения теста система считается готовой к пилотному запуску с реальными данными.
